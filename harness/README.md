# 포트폴리오 하네스

이 문서는 포트폴리오 사이트를 개발할 때 따르는 프로젝트 하네스입니다.

## 원칙

- React + TypeScript 표준 규칙을 따른다.
- UI는 단순하고 읽기 쉬운 구조를 우선한다.
- 공용 컴포넌트와 공용 스타일을 먼저 사용한다.
- 페이지, 데이터, 컴포넌트, i18n 사전을 분리한다.
- 한국어를 기본 언어로 작성하고 영어 사전을 함께 유지한다.
- 테스트와 문서는 필요한 시점에 점진적으로 추가한다.
- 새 페이지와 프로젝트 상세는 기존 `project-detail/definitions` 구조를 먼저 참고해 일관되게 확장한다.
- 배포는 GitHub Pages 정적 export 구성을 기준으로 유지한다.
- 웹 페이지와 `/slides`는 서로 분리된 표현 계층으로 유지하며, 필요한 내용은 상호 보완적으로 연계한다.
- 웹과 슬라이드는 동일한 내용을 그대로 공유하거나 한쪽의 레이아웃을 재사용하지 않는다. 공용 원문·자산이 필요할 때만 별도 데이터로 연결하고, 웹은 탐색·상세 확인을 담당하며 슬라이드는 발표·요약·인쇄 맥락을 담당한다.
- 반응형 동작과 캔버스 단축키는 페이지마다 임의로 구현하지 않고 공용 `WorkflowCanvas`와 viewport 규칙을 따른다.
- 커밋 메시지는 Conventional Commits 규칙을 반드시 따른다.
